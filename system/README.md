# Poster Batch Generation System

Turns product photos + Excel copy (headline/subline text) into 4 branded
poster JPGs per product, rendered from one InDesign master template.

## Folder layout

```
02_System/
  templates/
    Poster_Master.indd   ← single template, 4 labeled pages. Never hand-edit
                            the placement/z-order; only duplicated at render
                            time, never saved over by the pipeline.
  data/
    manifest.csv          ← generated by step 1, human-reviewable before rendering
  scripts/
    01_build_manifest.py  ← matches Excel rows to image folders (fuzzy match)
    02_generate_posters.jsx ← InDesign render driver, reads manifest.csv only
    run_batch.sh           ← runs both steps in order
    _archive/              ← one-off scripts used to build Poster_Master.indd
                             originally (merge templates, fix z-order, fix
                             visibility). Kept for reference only — the fixes
                             are already baked into Poster_Master.indd, these
                             do not need to run again.
  output/
    <headline>/<headline>_<texttop|textbottom>_<service|denis>_<WxH>.jpg
  logs/
    generation_log.csv    ← one row per rendered file (or per error)
```

## The 4 page variants (in Poster_Master.indd)

| Page label         | Aspect | Text position | Subline used     |
|---------------------|--------|----------------|-------------------|
| `top_service`        | 1200×1200 | top    | Service subline |
| `top_denis`           | 1200×1200 | top    | DANIS subline    |
| `bottom_denis`        | 1200×1200 | bottom | DANIS subline    |
| `9x16_top_service`    | 1080×1920 | top    | Service subline  |

Each page has a `TextFrame` named `<<Headline>>` (paragraph 1 = headline,
paragraph 2 = subline) and an image placeholder (named `<<MainImage>>`, or
the sole full-bleed rectangle if unnamed). The render script only ever reads
these labels/names — it never guesses based on filenames.

## How to run

```bash
02_System/scripts/run_batch.sh
```

This:
1. Runs `01_build_manifest.py`, which reads
   `01_Assets/Excel/00_Text_DANIS+Service.xlsx` (sheet `AOZ+AOT`), scans
   `01_Assets/Pictures/`, fuzzy-matches each Excel headline to a product photo
   folder, and writes `02_System/data/manifest.csv`.
2. Runs `02_generate_posters.jsx` in Adobe InDesign 2026, which reads only the
   rows marked `status=matched` in `manifest.csv` and renders all 4 variants
   for each into `02_System/output/<headline>/`, logging every render (or
   error) to `02_System/logs/generation_log.csv`.

Always check `manifest.csv` before trusting a full run — it's the one
human-review checkpoint between fuzzy matching and rendering.

## Extending to new products

1. Add a new row to the `AOZ+AOT` sheet in
   `01_Assets/Excel/00_Text_DANIS+Service.xlsx` (headline, DANIS subline,
   Service subline).
2. Add the product's photos under a new subfolder in `01_Assets/Pictures/`.
   The pipeline prefers a file matching `*(web_1080p).jpeg` in that folder;
   falls back to any other image file if none found.
3. Run `02_System/scripts/run_batch.sh`.

## Running the full catalog (not just the test set)

`01_build_manifest.py` currently has a `TEST_HEADLINES` allow-list scoping it
to 3 verified test products (Ski- und Snowboardhalter, Allwetterfußmatten,
Grundträger). To process everything, open the script and set:

```python
TEST_HEADLINES = None
```

With this set, unmatched Excel rows are written as `status=skipped_no_image`
and unmatched image folders are appended as `status=skipped_no_excel_row`, so
nothing is silently dropped — review these in `manifest.csv` after each run.

Known items that currently have no confident match on one side or the other
(as of the initial 3-product test pass):
- Image folders with no matching Excel row: Smartphone Interface,
  Marderabwehr, Fondschutzdecke, Gepäckraumschale, Gefrierschutz.
- Excel rows with no matching image folder: Wartung und Inspektion,
  HU-Service, Batterie Check.

These will need either a naming fix (Excel headline vs. folder name) or
missing assets added before they can render.

## Troubleshooting

- **Blank/white areas in output**: check `<<MainImage>>` and `<<Headline>>`
  visibility and z-order in `Poster_Master.indd` — the render script forces
  `visible=true` on every item defensively, but z-order must have Headline in
  front of the image, image in front of the background rectangle.
- **Errors in `generation_log.csv`**: most common causes are a missing image
  file (bad `image_path` in manifest.csv) or a page `label` that doesn't match
  one of the 4 expected labels in `02_generate_posters.jsx`.
- **`~poster_master~*.idlk` file in `templates/`**: a stale InDesign lock
  file; safe to ignore/delete once InDesign is confirmed closed.
